# Dashboard Specification

Dokumen ini mencatat spesifikasi dashboard awal yang akan dipakai untuk kebutuhan operasional dan supervisi.

## 1. Tujuan dashboard
Dashboard harus membantu pengguna memahami:
1. apa yang sedang ditangani,
2. apa yang membutuhkan tindakan,
3. apa yang tertunda,
4. apa langkah berikutnya,
5. prioritas atau batas waktu jika relevan,
6. riwayat pekerjaan yang relevan.

## 2. Struktur dasar
Setiap dashboard utama harus memiliki:
- header halaman
- ringkasan status
- daftar item prioritas
- daftar tugas yang menunggu tindakan
- ringkasan kejadian/insiden aktif
- panel kebutuhan review / approval
- riwayat aktivitas utama

## 3. Modul utama yang perlu ada
- Dashboard
- Insiden
- Aktivitas
- Assessment
- Relawan
- Inventaris
- Distribusi
- Donasi
- Keuangan
- LPJ
- Administrasi

## 4. Prinsip UX
- Desain konsisten.
- Navigasi sederhana.
- Bahasa operasional, tidak teknis.
- Hindari informasi berlebihan yang menggantikan antrean kerja.
- Dashboard bukan sekadar kumpulan grafik tanpa konteks keputusan.

## 5. Catatan desain
- Frontend mengikuti pendekatan SPA.
- Formulir harus memisahkan bagian dan menjaga validasi yang jelas.
- Data yang sudah diinput sebelumnya tidak perlu diulang.
- Draft aman jika mekanismenya sesuai.
